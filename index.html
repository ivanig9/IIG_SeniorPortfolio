My Projects

Here's stuff I've built—some are small experiments, some are bigger collaborations. Each one taught me something new about programming, design, or working with other people.

Animation Drawing

This was my first time making something actually move on the screen. I took a static drawing I made and added animation to it—learning how time actually works in programs. You have to think carefully about updates, frames, and states if you want motion to feel right.

Skills: Python, CodeSkulptor, Animation, Managing State

What I Learned: Animation isn't magic—it's just changing things really fast. Understanding how programs handle time and updates is huge for games.

Holiday Remix - Audio Design

Sound is honestly something people don't think about enough in games, but it's huge. I made a remix and realized how much music shapes what you're feeling. You can make the same game feel completely different depending on the audio.

Skills: Python, EarSketch, Audio Design, Composition

What I Learned: Audio tells a story just as much as visuals do. Patterns and repetition are how you build emotional moments in music.

Game Arcade - Team Project

This was the first time I worked on something with other people on the same codebase. We each made a different game and had to get them to work together in one system. It was messier than individual work, but also more realistic and much more valuable.

Skills: Python, CodeSkulptor, Teamwork, Modular Code, Testing

What I Learned: Your code has to make sense to other people, not just you. Communication is honestly more important than having super clean code.

Holiday Drawing - Visual Design

I drew a holiday scene using only code—circles, rectangles, and lines positioned exactly where they needed to be. No fancy art tools, just coordinate math. It was actually pretty fun to see how much you can do with simple shapes and careful placement.

Skills: Python, CodeSkulptor, Graphics, Composition

What I Learned: Constraints force you to be creative. Also, where you place things matters way more than it seems like it should.

Harvest Hope - Solving Real Problems

Our group spent a lot of time on this one. We designed an app to help with world hunger using research, prototypes, and user feedback. It felt different from other projects because we were solving something bigger than a classroom assignment.

What I Learned: Design is a responsibility. If you're making something for real people to use, you have to think about whether it actually helps them and if it's accessible.

How I Actually Work

I don't just sit down and build something perfect the first time. Here's roughly how I approach projects:

1. Figuring Out Ideas

I start by throwing ideas at the wall. I sketch, I write down mechanics, I think about what would be fun to play or use. I try to spot problems early before I waste time building something that doesn't work.

2. Planning It Out

I sketch wireframes and flowcharts to map out how things connect. For games, I think about controls, menus, and what happens when. Planning on paper saves me a ton of headaches later.

3. Building and Testing

I make a rough version and get people to use it. I watch what they do. Usually what I thought would be fun isn't, and things I didn't expect break. That's actually the whole point—figuring out what needs work.

4. Fixing and Polishing

Based on what I learned, I fix the mechanics, improve how it feels, and make it look better. Then I usually do the whole thing again because there's always more to improve.

Learning the Fundamentals

These are the building blocks I worked through. Each one taught me something I use in bigger projects now.

First Program

Starting point—printing stuff and reading user input. Sounds simple but this is how everything works. You ask the computer to do something, it does it.

Concept: Input/Output, Program Flow

ASCII Art

Making pictures with text characters. Sounds goofy but it teaches you how to think about arranging things and controlling what you output.

Concept: String Formatting, Escape Sequences, Creativity with Code

Math Operations

Learning how to do calculations. Order of operations matters. Game programming uses a lot of math—physics, positioning, everything really.

Concept: Operators, Precedence, Problem Solving

Rectangle Area Calculator

Taking a real problem (finding the area of a rectangle) and making a program solve it. This is where code starts to be actually useful.

Concept: Variables, Functions, Breaking Problems Down

Piggy Bank

Keeping track of numbers adding up over time. This is literally how games track your money, health, score—everything that changes during gameplay.

Concept: State, Tracking Data, Accumulation

Random Math

Adding randomness to math. Games need randomness—it makes things unpredictable and fun. Without it, games would be boring.

Concept: Randomness, Variety, Game Feel

If/Then Logic

Making your program make decisions. This is when programs stop being linear and start actually responding to what's happening.

Concept: Decision Making, Branching, Reacting to Things

Counting by Tens

First time using loops. Instead of writing the same code over and over, you write it once and repeat it. This changes everything.

Concept: Loops, Repetition, Efficiency

Decimal Counting

Loops with decimal numbers, not just whole numbers. Games care about precision—movement speeds, animations, physics—all decimals.

Concept: Floating-Point Numbers, Precision, Smooth Movement

99 Bottles of Beer

A loop that generates an entire song. One loop, lots of output. It's weirdly cool to see how much a simple pattern can do.

Concept: Loops with Strings, Patterns, Elegant Code

Happy Dots

First time drawing on screen with coordinates. This is where programming becomes visual. Points on a canvas are just numbers—that's the whole idea.

Concept: Coordinates, Graphics, Spatial Thinking

Happy Lines

Drawing lines between points. Lines connect stuff. Understanding this is important for everything visual.

Concept: Lines, Vectors, 2D Space

Happy Shapes

Drawing polygons and more complex shapes. You learn that shapes are just numbers—their properties are parameters you can control.

Concept: Polygons, Parameters, Shape Composition

Happy Circle

Drawing circles of different sizes and positions. This wraps up the basics of graphics primitives. You now know how to think in coordinates and turn ideas into visual code.

Concept: Circles, Graphics Fundamentals, Visual Programming
